# 매달얼마 기획서

**부제:** 구독·할부·보험·대출 한번에 정리
**패키지명(안):** com.devshwon.permonth
**플랫폼:** 토스 미니앱 + 안드로이드 (웹 기반)
**작성일:** 2026-09-02

---

## 1. 배경

카드 앱에 들어가면 "이번 달 결제금액 87만원"이라는 숫자 하나만 보인다. 그 안에 뭐가 들어 있는지는 아무도 알려주지 않는다.

- 할부는 산 시점에 50만원을 썼지만, 매달 빠지는 건 10만원이다
- 보험료, 구독료, 대출 원리금은 내가 아무것도 안 해도 매달 나간다
- 사람들은 이걸 "이번 달에 쓴 돈"으로 세지 않는다. 그래서 초과 지출한다

매달 자동으로 빠져나가는 돈의 총액을 아는 사람이 거의 없다. 알아야 줄일 수 있고, 알아야 남는 돈으로 계획을 세울 수 있다.

## 2. 목표

**한 문장:** 매달 자동으로 나가는 돈이 총 얼마인지 한눈에 보여준다.

### 하는 것
- 고정과금 항목을 등록해두면 월 총액을 계산해서 보여준다
- 항목별 금액·결제일·결제수단을 정리해서 보여준다
- 금액 큰 순으로 정렬해 사용자가 줄일 대상을 직접 판단하게 한다
- (보조) 카드 결제금액에서 고정분을 빼서 이번 달 실제 소비액을 역산한다

### 하지 않는 것
- 어떤 보험을 줄이라는 식의 추천이나 상담 (자격 문제 + 앱이 무거워짐)
- 식비·카페·교통 같은 변동지출 기록 → **매일 입력하는 가계부가 되는 순간 사용자가 이탈한다**
- 계좌 자동 연동 (오픈뱅킹 API는 개인 개발자에게 사실상 막혀 있음)
- 자산 총액 관리, 투자 관리

> **설계 원칙: 입력 횟수를 최소화한다.**
> 엑셀로 관리하다 그만두는 이유는 도구가 없어서가 아니라 매달 손대야 해서다.
> 고정과금은 한 번 등록하면 12개월 유효하다. 사용자가 앱을 여는 건 "확인"할 때지 "입력"할 때가 아니어야 한다.

## 3. 타겟

- 구독 서비스 3개 이상 + 할부 or 대출 or 보험이 있는 사람
- 매달 카드값을 보고 "왜 이렇게 많이 나왔지" 싶은 사람
- 가계부를 시도했다가 귀찮아서 포기한 경험이 있는 사람

## 4. 핵심 개념

### 4-1. 현금 기준으로 통일한다

같은 할부를 두 가지로 볼 수 있다.

| 관점 | 50만원 12개월 할부를 보는 방식 |
|---|---|
| 발생 기준 | 산 시점에 50만원을 썼다 |
| 현금 기준 | 매달 10만원씩 나간다 |

둘 다 맞지만 **한 화면에서 더하면 이중과금이 된다.** 이 앱의 목적은 "이번 달에 실제로 빠지는 돈"이므로 **현금 기준만 사용한다.**

**규칙**
- 할부는 구매 시점 총액(50만원)을 지출로 기록하지 않는다
- 월 납입액(10만원)만 고정과금으로 잡는다
- 총액과 잔여 회차는 **참고 정보**로만 표시한다 (예: "7/12회차, 잔액 30만원")

### 4-2. 항목 층과 출금 층을 분리한다

결국 모든 돈은 통장에서 나간다. 카드는 여러 건을 모아 결제일에 한 번에 빼갈 뿐이다.

**항목 층** — 사용자가 등록하는 단위

```
넷플릭스        17,000   신한카드
자동차 할부    320,000   신한카드
실손보험        45,000   국민은행 통장
전세대출 이자  180,000   국민은행 통장
```

**출금 층** — 실제로 통장에서 빠지는 단위

```
15일  국민은행    225,000  (보험 + 대출)
25일  신한카드    337,000  (카드 고정분)
```

잔고가 모자라는 사고는 항상 출금 층에서 난다. 25일에 얼마가 한 번에 빠지는지 보여야 대비가 된다.

### 4-3. 끝나는 날이 있는 항목을 구분한다

| 유형 | 종료 | 예시 |
|---|---|---|
| 무기한 | 없음 | 구독, 보험 |
| 유기한 | 있음 | 할부, 대출 |

**"3개월 뒤 할부가 끝나면 월 32만원이 풀린다"** — 이 정보는 다른 앱이 잘 보여주지 않는다. 줄일 걸 찾는 것만큼이나 계획을 세우는 데 필요하다.

## 5. 화면 구성

### 홈 (핵심 화면)

앱의 존재 이유가 이 화면 하나에 담긴다.

```
─────────────────────────
 이번 달 고정과금
      562,000원
─────────────────────────
 자동차 할부   320,000  25일  7/12회차
 전세대출이자  180,000  15일
 실손보험       45,000  15일
 넷플릭스       17,000  25일
─────────────────────────
 3개월 뒤 320,000원이 풀립니다
```

- 총액을 가장 크게
- 금액 내림차순 정렬 (줄일 대상이 자연스럽게 위로)
- 유기한 항목은 잔여 회차 표시

### 항목 등록/수정
- 이름, 금액, 결제일, 결제수단, 카테고리(구독/할부/보험/대출/기타)
- 유기한이면 총 회차와 시작일 → 종료 시점 자동 계산
- 입력 필드는 최소로. 이름과 금액만 필수

### 출금 달력
- 날짜별로 어느 계좌·카드에서 얼마가 빠지는지
- 결제일이 몰린 날 확인용

### 카드값 역산 (보조)
```
카드 앱 결제금액   870,000  ← 사용자가 직접 입력
카드 고정분        337,000  ← 앱이 계산
───────────────────────────
이번 달 실제 소비  533,000
```

**한계를 명시할 것:** 앱이 아는 건 고정분까지다. "카드값 중 최소 337,000원은 확정"이라는 표현이 오해가 없다.

## 6. MVP 범위

첫 버전은 주말에 끝낼 수 있는 규모로 자른다.

**포함**
- 항목 CRUD
- 월 총액 계산 + 정렬된 리스트
- 결제수단 구분 (카드/통장)
- 로컬 저장

**제외 (2차 이후)**
- 출금 달력
- 카드값 역산
- 결제일 알림
- 잔여 회차·종료 예정 알림
- 클라우드 동기화

> 첫 버전 완성 후 **본인이 최소 두 달 연속 사용**하는지부터 확인한다. 그게 안 되면 남도 안 쓴다.

## 7. 기술

| 항목 | 선택 | 이유 |
|---|---|---|
| 프론트 | 웹 (PWA) | iOS 개발자 계정 없이도 전 플랫폼 커버 |
| 저장 | 로컬 우선 | 데이터가 항목 리스트 하나라 서버 불필요, 요청 수 0 |
| 인프라 | Cloudflare Pages | 기존 계정 유지, 무료 티어로 충분 |
| 안드로이드 | WebView 래핑 | 기존 개발자 계정 활용 |
| 토스 | 미니앱 | 설치 없이 진입 가능 |

**계정 분리는 하지 않는다.** 프로젝트는 `permonth-*` 접두어로 구분. 계정을 쪼개면 DNS·토큰·배포가 이중화되고 이관이 어려워진다.

## 8. 수익

**광고는 기대하지 않는다.** 유틸 앱은 유저 의도가 광고와 이어지지 않아 eCPM이 낮게 형성된다. 로또 앱처럼 금융 광고주가 붙는 카테고리가 아니다.

**단기:** 수익 모델 없이 출시. 본인 사용 지속 여부부터 검증.

**중기 가능성**
- 카드·보험 제휴 (단, 추천은 안 한다는 원칙과 충돌하므로 신중히)
- 항목 수 제한 해제 등 소액 결제

## 9. 배포

**만들기 전에 정할 것: 어디에 있는 누구에게 어떻게 보여줄 것인가.** 배포 경로가 없는 아이디어는 만들지 않는다.

| 채널 | 각도 |
|---|---|
| 스레드 | 만드는 과정 자체를 연재. 완성품 던지는 건 광고로 읽힌다 |
| 짠테크·재테크 커뮤니티 | "고정지출 정리" 각도. 가입 후 며칠 눈팅 → 홍보 게시판 확인 후 글 |
| 토스 미니앱 | 설치 장벽 없음이 최대 강점. 링크 하나로 공유 |

같은 날 여러 곳에 뿌리지 않는다. 채널별로 나눠야 어디서 유입이 오는지 구분된다.

## 10. 스토어 메타

**부제 후보 (20자)**
1. 구독·할부·보험·대출 한번에 정리 (18자) — 키워드 4개 포함, ASO에 유리
2. 매달 자동으로 나가는 돈, 한눈에 (18자)
3. 내가 모르는 사이 나가는 돈 확인 (18자)

**상세설명 (100자)**
> 통장에서 매달 알아서 빠져나가는 돈, 다 합치면 얼마일까요. 구독부터 대출까지 한 곳에 모아두면 총액이 보이고, 줄일 항목도 직접 골라낼 수 있습니다.

**검색 키워드**

| 구분 | 키워드 |
|---|---|
| 핵심 | 고정지출, 고정비, 매달나가는돈, 자동결제, 정기결제 |
| 항목별 | 구독관리, 구독료, 할부관리, 보험료관리, 대출상환, 카드값 |
| 목적별 | 지출관리, 지출줄이기, 절약, 새는돈, 생활비관리 |
| 상황별 | 결제일알림, 월지출, 한달지출, 고정비계산 |

"가계부"는 검색량이 크지만 뱅크샐러드 등이 독점하고 있어 실익이 없다. 경쟁이 덜한 "구독관리", "할부관리" 쪽에서 상위 노출을 노린다. 이 키워드로 오는 사용자는 이미 문제를 인식한 상태라 전환율도 높다.
